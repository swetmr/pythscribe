# Differential fuzz: `grammar/pyths.lark` vs the authoritative parser

Generated by `scripts/grammar-fuzz.py` (seed `20260714`). Re-run:

```bash
pip install lark
cargo build --release --workspace

# headline numbers (needs the external held-out corpus)
python scripts/grammar-fuzz.py --generate 10000 --extra-corpus <path-to-held-out-corpus>

# CI gate (hermetic; in-repo corpora + corpus-free generation)
python scripts/grammar-fuzz.py --generate 2000 --fail-on-new
```

## Why this exists

`scripts/test-grammar.py` proves the grammar **accepts** a fixed tracked corpus.
That is one direction, on one corpus. It is blind to everything the grammar
accepts that `pyths` rejects, and it says nothing about code outside the corpus.
Parser equivalence is undecidable and we do not claim it — but the gap can be
**bounded empirically**, in both directions.

The comparison is **parse-vs-parse**. `pyths check` runs the parser *and* the
type checker, so the fuzzer calls `pyths check --syntax-only` (added for this
purpose): a type error must never be scored as a grammar false-accept, because
the Lark grammar is a syntactic acceptor and can only be compared to a syntactic
oracle.

## Headline

| Direction | Meaning | Rate | Sample |
|---|---|---|---|
| **False accept** | grammar accepts, authoritative parser rejects | **0.120 %** | 12 / 10,000 generated derivations |
| **False reject** | parser accepts, grammar rejects | **0.000 %** | 0 / 21,033 programs |

Before this work: **false accept 70.700 %**, false reject 2.540 % (dev split).

### False accepts — method

Random derivations are generated **from the LALR rule set of the grammar
itself**, so grammar-acceptance holds by construction; each rendered string is
then re-parsed with the same grammar (self-check) and run through
`pyths check --syntax-only`. Strings whose *rendering* is not faithful (token
adjacency) fail the self-check and are discarded as **generator artifacts** —
2,961 of 12,961 draws (22.8 %). They are excluded from both numerator and
denominator, so the rate is over the 10,000 self-verified strings. This means
the rate is a statistic over the generator's distribution on the *renderable*
subset of L(grammar), **not** a probability that realistic code is invalid.
The durable finding is the *set of divergence classes*; the rate is a sampling
statistic.

### False rejects — method and the held-out split

Population = parser-valid programs + semantics-preserving **mutations** of them
(rename identifiers, inject comments/blank lines, pad whitespace, vary trailing
newlines, re-indent at 2/8 spaces). Every mutant is re-validated by the
authoritative parser and discarded if the parser rejects it, so a buggy mutation
can never be scored as a grammar false-reject.

The grammar was developed against the in-repo corpora, so measuring only there
would be measuring on the training set. The external held-out corpus (real `.ps` sources and generation-eval
completions — never seen by the grammar gate) is deterministically halved by SHA-1 of the path:

| Split | What it is | False rejects |
|---|---|---|
| `dev` | in-repo; the grammar was developed on it | 0 / 4,760 (0.000 %) |
| `held-A` | external; fixes may be driven by it | 0 / 8,039 (0.000 %) |
| `held-B` | external; **frozen**, never inspected while fixing | **0 / 8,234 (0.000 %)** |

## Divergences found, and how each was triaged

**11 classes fixed in the grammar** (the grammar was wrong — it over-accepted):

| Class | Grammar accepted | Parser says |
|---|---|---|
| `match` as a general identifier — **36.4 % on its own** | `import match`, `def match()`, `global match` | `Expected identifier, found match` |
| float literal patterns | `case 1.5:`, `case -1.5:`, `case [1.5]:` | `Unexpected token in pattern: Float` |
| f-string literal patterns | `case f'a':` | `Unexpected token in pattern: FString` |
| bare / parenthesised sequence patterns | `case a, b:`, `case (a, b):`, `case ():` | `Expected :, found ,` |
| `**rest` in a mapping pattern | `case {**rest}:` | `Unexpected token: **` |
| keyword sub-patterns in class patterns | `case P(x=1):` | `Expected ), found =` |
| dotted class-pattern heads | `case a.b():` | `Expected :, found (` |
| loop targets as general expressions | `for o.x in p`, `for -x in p`, `for * * b in p` | `Expected in, found .` |
| `with ... as <expr>` | `with a as b.c:`, `with a as b[0]:` | `Expected :, found .` |
| class bases with kwargs / `**` | `class C(metaclass=M)`, `class C(**k)` | `Expected ), found =` |
| slices inside a subscript tuple | `a[:,]`, `a[1:2, 3]` | `Unexpected token: ,` |
| trailing bare `*` in a parameter list | `def f(*)` | `Expected identifier, found )` |
| non-NAME keyword-argument LHS | `f(() = 1)`, `f(a.b = 1)` | `Invalid keyword argument` |
| trailing comma before `:` / augassign op | `a,: int = 1`, `*(), >>= True` | `Unexpected token: :` |
| `lambda` in a comprehension `if` | `[i for i in p if lambda: True]` | `Unexpected token: lambda` |
| f-string side-effect import path | `import f'a.css'` | `Expected identifier` |

**4 bugs fixed in the AUTHORITATIVE PARSER** — here the *grammar* was right and
`crates/pyths_parser` was the over-accepting / wrongly-rejecting side:

1. **`;` was missing from three statement-terminator sets.** A one-line suite
   ends a simple statement with `;`, but `parse_return_stmt`, `parse_raise_stmt`,
   the side-effect-import guard, and `parse_expr_list`'s bare-tuple terminator
   only recognised NEWLINE/EOF. So `if x: return;`, `if x: raise;`, `if x: a,;`
   and `if dev: import "./a.css";` were all rejected — although `pass;`,
   `break;`, `del a;` and `return 1;` worked. *(→ `test_bare_return_and_raise_accept_semicolon_terminator`,
   `test_semicolon_terminates_bare_tuple_and_side_effect_import`)*

2. **Simple statements did not require a terminator at all.** Every simple-statement
   parser ended with `self.eat(&Token::Newline)`, which is a **no-op** when the
   next token is not a newline; the statement loop then just began a new
   statement wherever the last one stopped. The parser therefore silently
   accepted token soup with no separator:

   ```
   x = 1 y = 2      pass pass      a b      import os x = 1      greet = abc"z"
   ```

   all parsed, as two statements each. `grammar/pyths.lark` requires
   `simple_stmt: small_stmt _NEWLINE` and had always rejected them. Fixed with a
   central `expect_stmt_end()` (NEWLINE | `;` | DEDENT | EOF).
   *(→ `test_simple_statements_require_a_terminator`)*

## The residual — 0.120 %, deliberately not closed

All 12 remaining false accepts are one root cause: **`yield` is an `atom`**, so
`atom_expr` can hang a postfix trailer off a bare `yield` (`yield?.[k]`,
`yield.attr`) and `yield` can appear in tuple / `del` / one-line-suite positions
the parser refuses.

It is left open **on measurement**. The obvious fix — hoisting `yield_expr` out
of `atom` up to `test` — makes `yield` derivable in *every* test position and
drives the false-accept rate from **2.6 % to 64.3 %**. A correct fix needs a
yield-aware expression level that LALR(1) cannot express here without a
conflict. The over-acceptance requires a bare `yield` in an operand position and
is unreachable from realistic code. Tracked as `KNOWN_DIVERGENCES` in
`scripts/grammar-fuzz.py`; CI fails on any *new* signature.

## What this does and does not establish

It establishes that, on these samples, the grammar rejects nothing the parser
accepts (0 / 21,033, including 0 / 8,234 on a frozen held-out split), and that
what it accepts beyond the parser is confined to one characterised, unreachable
construct.

It does **not** establish equivalence — that is undecidable, and the false-accept
figure is a statistic over a generator distribution, not a bound over L(grammar).

It says **nothing about semantics.** The grammar is a *syntactic* acceptor: no
CFG can exclude undefined names, wrong arity, or type errors. `x = "a" - 3` is
grammar-valid *and* `pyths check`-valid. Constrained decoding on this grammar
guarantees the output **parses** — not that it means anything.

## Addendum — E7 conformance-corpus sync (2026-08-31)

The E7 recurring conformance net vendored 47 Transcrypt autotester testlets
(`tests/conformance/autotester/testlets/`) into the repo. The fuzzer's [B]
harvest picked them up and measured **67 false rejects** (12 parser-valid base
testlets + their mutants): real Python surface `pyths_parser` accepts that the
grammar had never modeled. All were closed by MODELING the constructs (no
ledger padding, no harvest exclusions), each boundary re-measured against
`pyths check --syntax-only` first (~170 probe cases):

imaginary literals (decimal forms + `j/J` only) · byte strings (`b`/`B`,
single-line, bytes-with-bytes concat only) · one underscore after a base
prefix (`0x_ff`) · dot-hanging floats (`2.`, `.5`, `2.e3`) · full free-order
lambda params (`*args`/`**kw`/keyword-only) · subscript tuples with slices and
stars (`a[1:2, 3:4]`, `a[*b]`) · general `;` chaining (trailing `;`, top-level
chains, compound as final `;`-item, compound as inline suite) · `@` matmul +
`@=` · for-iter and `return` testlists (star items, trailing comma) ·
continuation `\` followed by blank/comment lines.

Post-sync CI-gate run (seed 20260714, `--generate 2000 --fail-on-new`, on
the shipped r2 grammar): **false rejects 0 / 7,029** (1,698 base + 5,331
mutants — now including the testlet corpus); false accepts 213 / 2,000
(10.650 %). Two honest caveats on the false-accept side (r1/r2 adversarial
reviews, SF-1 + the codex ratification round): (a) the *rate* is a sampling
statistic over the regenerated derivation walk and is not comparable
run-to-run; (b) the gate's precise guarantee is **no new NORMALIZED
PARSER-ERROR SIGNATURE** (`classify()` collapses lexemes/digits and keys on
the parser's message; the ledger is untouched) — every post-sync false
accept normalizes to a pre-existing `KNOWN_DIVERGENCES` signature
(flow-context `return`/`break`/`continue`, dup-param, and the `yield`
residuals). That is weaker than "no new semantic divergence class": some
*ledgered* signatures got **wider** (e.g. `return 1j` at module level, a
bare `yield` inside the new `for`/`return` testlists), and a hypothetical
new class whose parser message collapses to a generic ledgered signature
(`Unexpected token: ,` etc.) would pass the message-keyed gate unseen. The
claim this gate supports is "no new signature", not "no new over-accepted
string" — the cross-checked probe suites (r1 ~490 + r2 ~330 three-way
probes) are the compensating control on the shipped boundary. The headline table above (10,000 draws + held-out
corpus) predates this sync and documents that campaign;
`grammar-fuzz-results.json` is its frozen record. The parser was NOT
touched; `scripts/test-grammar.py`'s vendored-testlet prefix exclusion is
retired (the corpus is now hard-gated; the one parser-rejected testlet,
`metaclasses.ps`, moved to `PS_EXCLUSIONS`), and the measured accept/reject
boundaries are pinned as paired witnesses in its new corpus 5
(`PINNED_WITNESSES`) — the negative control that would have caught the r1
review's BLOCKER-1 (a continuation-`%ignore` regression at EOF, invisible
to corpus gates because no tracked file ends in a `\` continuation).
