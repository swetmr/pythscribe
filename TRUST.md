*Added 2026-07-10 (testing gap-closure §7.7). This is the honest-measurement
invariant made checkable: every guarantee below names its enforcement
mechanism and the command that regenerates its evidence. Structure follows
the four Axon validation phases (testing / credible compilation /
verification / audit).*

| **Tier B is concrete, not opaque:** the kwarg tier is instantiated over the SHIPPING 9-entry `kwargs.rs` table; its rewrite is *decided* to be exactly that table, it is zone-safe at char level, and it fires only in call-argument position (never in statement position, before `==`, in a string/comment, or on a non-table identifier) | `committed_kwargs_exact`, `kwargs_position_discipline`, `kwarg_zone_safety_chars`, `tierB_zone_safety`, `tierB_length` | `lake build` + `gen-kwarg-data.py --check` (Lean-side drift) + `kwarg-fnv1a64` in `model-manifest.txt` (Rust-side drift) + `diff_harness.py --tier kwargs` (432 cases) |

**Trust base.** Two tiers, stated exactly:

- **Segment/tier/route lemmas** (`expand_zone_safety`, `route_read_safety`,
  `protChars_sublist_input`): `propext` only.
- **WASM-admission soundness** (`wasm_admission_sound`): `propext`,
  `Quot.sound` — `Quot.sound` enters via the `Option`/`Bool` `simp` normal
  forms over the executable `toWasmType`, the same standard base the
  classifier theorems rest on. Pinned by `#guard_msgs`.
- **Classifier theorems over the executable scanner** (`zone_safety_chars`
  and friends): `propext`, `Classical.choice`, `Quot.sound` — Lean's three
  standard axioms, the base mathlib runs on. These are **inherited from Lean
  core's `String`**, not introduced by our proofs: `#print axioms
  expandDictChars` reports the same three for the *unmodified* shipped
  definition, because it calls `String.ofList` / `String.toList`.
- **0 proof holes, 0 kernel-bypassing evaluation, 0 axioms of our own.**

Enforced two ways: the CI trust-base audit step (greps for escape hatches)
**and** `#guard_msgs`-pinned `#print axioms` assertions inside
`PythExpandVerify.lean` — if anyone introduces a proof hole or a new axiom,
the printed axiom list changes and `lake build` **fails**. The trust base is
checked by the build, not asserted in prose.

**Statement-review gate (the kernel cannot catch a weakened statement).** A
green `#print axioms` with zero `sorry` over a *weakened* theorem is vacuous —
the failure mode CertiCoq's AT hit (a dropped fuel bound → trivially true) and
the proof-level twin of #363 (`wasm_admission_sound` green because the
*predicate* was wrong). So every theorem statement — and the executable
definitions it quantifies over (a wrong `slice.indices`/route model makes even a
true theorem useless) — is reviewed **independently of whoever wrote the
proof**, on three axes:
- **Not silently weakened:** no hypothesis turned trivial, no precondition
  strengthened to vacuously exclude inputs, no postcondition relaxed below what
  the validated spec said. Diff the final statement against the approved spec.
- **Not vacuous:** where a theorem carries several preconditions, they are
  collapsed into one decidable `Bool` checker, `checker = true → Preconditions`
  is proved, and the checker is *evaluated on concrete inputs* so Lean certifies
  the input space is non-empty (the Move-borrow-checker technique).
- **Faithful to reality:** the executable model is differentially bound to the
  reference (CPython) and the shipped artifact on a boundary-heavy corpus, so
  the spec is validated *before* it is proved (PBT refutes cheaply; the proof
  certifies). See `lean-spec-quality` skill + `lean_papers_insights.md §9`.

**Statement ownership stays human, permanently** — an AI prover may fill a proof
but never redraft the statement it proves.

**Model-to-implementation binding** (proofs are about the real compiler,
not a drifting model):
- `verification/model-manifest.txt` pins tier order + dictionary FNV
  (`cargo test -p pyths_expand --test gates`).
- Executable-model differential: `lake exe expanddiff` vs real
  `pyths expand` — **two arms**, both byte-identical, in CI
  (`python verification/diff_harness.py`): dictionary tier (418 cases) and
  Tier B kwarg aliases (432 cases).
- **Lean↔Python transliteration drift gate** (C10): **wired into CI** —
  `.github/workflows/ci.yml` runs `python spec_lean_drift.py` in the Lean job
  AFTER `lake build`, and the script itself FORCES a fresh `lake build` before
  `lake env lean` so it can never compare against a stale `.olean`.
  `verification/spec_lean_drift.py` generates a Lean `#eval` harness that
  EXECUTES the real Lean model functions (`d2Lookup`/`d2Keys`/`d2Mem`/`smFindSub`/
  `smCount`/`smReplace`/`jsObjLookup`/`js16FindSub`/…) on a shared corpus via
  `lake env lean`, and diffs the output against the SAME corpus run through the
  `spec_validate_*.py` Python transliterations (418 cases). This binds the Stage-3
  transliterations to their Lean source, so a later Lean edit that drifts from its
  Python twin fails the gate instead of passing silently. **It does NOT catch a
  SYNCHRONIZED Lean/Python bug** (both sides sharing the same wrong logic still
  agree, so the gate passes) — the separate CPython differential inside
  `spec_validate_*.py` is the backstop for that class. (The drift gate complements,
  does not replace, the CPython differential.)
- Generated-table drift gates: `gen-dict-data.py --check` and
  `gen-kwarg-data.py --check` (Lean side) + `dict-fnv1a64` /
  `kwarg-fnv1a64` in `model-manifest.txt` (Rust side) — neither side can
  move alone.
- Route-table: `verification/route-table.txt` checked from Lean
  (`lake exe expanddiff --check-route-table`) AND Rust
  (`cargo test route_table_matches_committed_fixture`).
- WASM-admission table: `verification/wasm-admission-table.txt` (232 boundary
  shapes × `is_wasm_eligible`/`to_wasm_type` bits) checked from Lean
  (`lake exe expanddiff --check-wasm-admission-table`) AND Rust
  (`cargo test wasm_admission_table_matches_committed_fixture`) — neither the
  admission rule nor the lowering can move without breaking its own gate.
  Every row also witnesses `wasm_admission_sound` finitely (no elig=1,lower=0).

## Trusted (audited, not proved — the audit surface, ranked)

1. **`.ps`→JS/WASM codegen** (`pyths_codegen_js` 500+ tests,
   `pyths_codegen_wasm` 148) — audited by the differential + parity
   layers above; the subscript-routing pass now carries certificates, and
   WASM auto-routing admission carries a soundness certificate + Lean theorem
   (the *boundary* half — types + lowering — is machine-checked; the *body
   fragment* half stays differential/Livermore-tested, per the cert's honest
   trust boundary).
2. **The Rust byte scanner in `strings.rs`** — the *Lean* char-level
   classifier is now proved zone-safe (see above); what remains trusted is
   only that the Rust byte scanner **refines** it. That refinement is
   differential-bound (418 cases, byte-identical, in CI) + property-tested
   (300 seeded cases), not proved. This is a strictly smaller trusted surface
   than before: previously the classifier's *logic* was unproved; now only
   its *Rust re-implementation* is.
3. **Type-inference evidence** in routing certificates — the checker
   validates rule application, not the inference; inference is covered
   by the differential layers.
4. **The runtime JS** — 132 runtime/format tests + packaging installs.
5. **Toolchain** (rustc, Lean 4.31.0 kernel, Node, CPython-as-oracle).
